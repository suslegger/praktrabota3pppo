# Практическая работа № 3 по дисциплине "Паттерны проектирования программного обеспечения"

### Разработка программ с использованием принципа единственной обязанности (SRP) и принципа открытости/закрытости (OCP)
### Цель работы: получить навыки разработки программ с использованием принципа единственной обязанности (SRP) и принципа открытости/закрытости (OCP).

В репозитории две реализации одного и того же сценария:

| Ветка | Вариант | Описание |
|---|---|---|
| `beginner` | 1. Без применения принципов | Один класс, параллельные массивы, вся логика в одном методе. Работает, но нарушает SRP и OCP. |
| `solid` | 2. По принципам | Слои, интерфейсы, стратегии, внедрение зависимостей. SRP и OCP соблюдены. |


## Сценарий использования

Обслуживание заявки на неисправность АРМ в модуле технической поддержки:

1. Сотрудник оставляет заявку о проблеме с АРМ.
2. Оператор принимает заявку в работу.
3. Система считывает телеметрию с АРМ (диск, сеть, температура, питание).
4. Диагностика выявляет неисправность.
5. Если неисправность устраняется удалённо — система открывает удалённый сеанс
   и устраняет её.
6. Если удалённо устранить нельзя — выводится местоположение АРМ; если оно
   отличается от местоположения оператора, строится маршрут до АРМ.
7. Большая языковая модель (в прототипе — офлайн-заглушка) формирует ответ
   сотруднику.
8. Заявка переводится в статус `RESOLVED` или `ESCALATED`.

Демонстрационные заявки:

| № | Заявка | АРМ | Неисправность | Результат |
|---|---|---|---|---|
| 1 | TCK-1001 | WS-101 | мало места на диске | устранено удалённо |
| 2 | TCK-1002 | WS-205 | нет сети | устранено удалённо |
| 3 | TCK-1003 | WS-310 | перегрев процессора | выезд, маршрут 3,7 км |
| 4 | TCK-1004 | WS-415 | сбой питания | выезд, АРМ в том же здании |

## Как запустить

Требования: .NET SDK 8.0 или новее, поддерживаемая им ОС, современный терминал.

1. Выбрать нужную ветку (beginner или solid)
2. Запустить проект с помощью dotnet sdk:
Из корня репозитория:
```powershell
dotnet run --project .\src\ItSupport.Beginner.csproj
```

Сборка исполняемого файла без запуска:

```powershell
dotnet build .\src\ItSupport.Beginner.csproj
```

### Проверка работы программы

1. Запустите приложение
2. Введите номер заявки (`1`–`4`) и нажмите Enter.
3. Прочитайте журнал обработки, нажмите Enter для возврата к списку.
4. Обработайте остальные заявки, затем введите `0` для выхода.

Ожидаемые статусы после обработки всех заявок:

```
1. [RESOLVED]  TCK-1001
2. [RESOLVED]  TCK-1002
3. [ESCALATED] TCK-1003
4. [ESCALATED] TCK-1004
```

Повторно обработать уже закрытую заявку нельзя — приложение выведет
предупреждение.

## Структура проекта

Структура показана для ветки `solid`. В ветке `beginner` структура отличается

```
├── README.md                     # данный файл
└── src/                          # вариант 2: слои и абстракции
    ├── Domain/                   # модели: Ticket, Workstation, Fault, Location, Route
    ├── Diagnostics/              # правила диагностики + служба диагностики
    ├── Remediation/              # стратегии устранения и планировщик
    ├── Routing/                  # построение маршрута
    ├── Ai/                       # помощник для ответа сотруднику
    ├── Data/                     # репозитории и источник телеметрии
    ├── Application/              # сценарий обработки заявки
    ├── Presentation/             # консольный интерфейс и меню
    ├── Program.cs                # точка сборки (composition root)
    └── ItSupport.Solid.csproj
```

## Ограничения прототипа

- Все сторонние функции (построение маршрутов, подключение к БД, ИИ, АРМ) являются заглушками; данные заданы в `Program.cs`
- Обрабатывается основная (самая тяжёлая) неисправность из найденных.
